# Security and Threat Model Review

This document outlines the threat model, attack vectors, mitigations, and automated security verification probes implemented across the Rayda Fleet Copilot.

## Executed Chaos Penetration Probes

The automated security chaos harness (`scripts/security_chaos.py`) executes 41 adversarial probes against system boundaries, tool allowlists, and input validators.

Command: `python scripts/security_chaos.py`  
Result: **41 passed, 0 failed, 0 skipped**. The test suite lives in `apps/api/tests/test_security_chaos.py`.

## Release gate

`make eval-security` runs the 41-probe attacker CLI and then the security pytest suite. Any test failure fails the command. PostgreSQL integration skips also fail the security release gate; configure `TEST_DATABASE_URL`, `TEST_DATABASE_APP_URL` (must authenticate as `fleet_app`), and `TEST_DATABASE_INGEST_URL` before treating database guarantees as verified. A migration/owner connection is not accepted as RLS evidence.

The harness does not claim verification of production identity provider behavior, deployed browser security headers, secret-manager deployment, CORS/CSRF configuration under production topology, dependency vulnerability state, live OpenTelemetry scrubbing, or external connector execution. Those remain deployment or integration review items; no fake passes are reported for them.
